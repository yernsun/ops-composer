## Community support (no SLA)

Use the repository's issue tracker for reproducible defects and feature proposals. Use GitHub
Discussions for questions when it is enabled. Search existing threads first and include the
OpsComposer version or commit, deployment method, relevant sanitized logs, and reproduction steps.
Never post credentials, private keys, cookies, TOTP seeds, database dumps, inventories, customer
data, or vulnerability details in a public thread.

Community support is best-effort and has **no service-level agreement**. No response time,
resolution time, fix, release, upgrade, compatibility period, or continued maintenance is
promised. A maintainer may prioritize, defer, close, or decline a request. Using OpsComposer or
opening an issue does not create a support, consulting, fiduciary, or other contractual
relationship.

Report suspected vulnerabilities through the private process in [SECURITY.md](SECURITY.md).
Security reporting is not a paid service and does not require sponsorship.
